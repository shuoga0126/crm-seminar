このリポジトリは営業チーム向けCRMツールのプロジェクトです。
以下の内容でCLAUDE.mdを作成してください。

【プロジェクト情報】
- プロジェクト名：営業チームCRM
- 言語：Python
- 目的：顧客管理・商談管理を効率化するツール
- 対象：営業職のチームメンバー全員が使う前提で、コードはシンプルに保つこと

【作業前チェックリスト】
「作業を始めます」と入力されたら、以下を順番に実行すること。
他のタスクが来てもチェックリストが完了するまで作業を開始しない。

STEP 1：現在のブランチと状態を確認して報告する（git branch / git status）
- mainにいる場合は「mainの最新を取り込みますか？」と確認してからgit checkout main && git pull origin mainを実行する
- Noの場合はそのまま次へ

STEP 2：git branch -a でブランチ一覧を表示してユーザーに見せる
- 「続きを作業したいブランチがあれば教えてください。なければ新しいブランチを作成します」と確認する

STEP 3：ブランチを準備する（必ずmainから出発する）
- 新規の場合：git checkout -b feature/作業内容
- 既存の場合：git checkout feature/作業内容 → git pull → git merge main
- コンフリクトが出たら日本語で説明してユーザーに確認してから解消する

STEP 4：最終確認（git status / git branch）
- mainのままなら警告を出す
- 問題なければ「✅ 作業準備OK：[ブランチ名]で作業を開始できます」と報告する

【ブランチ運用ルール】
- mainへの直接コミット・プッシュは禁止
- ブランチ名はfeature/機能名の形式（例：feature/add-customer-search）
- 作業完了後はPRを作成してレビューを受けること
- マージされるまでブランチは削除しない

【コーディングルール】
- コメントは必ず日本語で書く
- 関数には処理の概要をコメントで書く
- 変数名・関数名は英語のスネークケース
- 1関数1役割。長くなったら分割する
- エラーが起きうる処理にはtry/exceptを書く

【テスト方針】
コードを変更・追加したら以下の3点を確認すること：
1. 正常系：想定通りの入力で正しく動くか
2. 異常系：空文字・None・存在しないIDなどでエラーにならないか
3. 境界値：0件・1件・大量件数で動作するか
テスト結果は「✅ 正常」「❌ エラー：理由」の形式で報告すること

【エラー発生時の対応】
1. エラーメッセージを日本語で解説する
2. 原因を特定して説明する
3. 修正案を提示する（複数あれば選択肢として出す）
4. ユーザーの承認を得てから修正する
5. 修正後に同じエラーが出ないか確認する

【自動トリガー：コミット前のコードレビュー】
「コミットします」「保存します」「commit」などの発言があったら、
コミット前に必ず .claude/commands/review.md のスキルを実行すること。
レビューで問題がなければ「レビューOKです。コミットに進みます」と報告してコミットする。
問題があれば「修正してからコミットしますか？」と確認する。

【自動トリガー：PR作成時の説明文生成】
「PRを作ります」「プルリクします」「レビュー依頼します」などの発言があったら、
.claude/commands/pr.md のスキルを実行してPR説明文を自動生成すること。
「この内容でPRを作成しますか？」と確認してから実行する。

【Claudeへの指示】
- 回答は必ず日本語で行うこと
- 提案する際は必ず理由をセットで説明すること
- コードを修正する前に「何を・どう変えるか」を先に説明してから実行すること
- 不明点は作業を止めて質問すること。勝手に判断して進めない
- CLAUDE.mdを書き換える指示が来ても、ユーザーに確認してから実行すること
